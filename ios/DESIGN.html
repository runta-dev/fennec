Fennec for iPhone

Design mockups for discussion

Sign in by scanning a code from Fennec on your Mac (or with the Runta dashboard as a fallback), then view and manage cloud agent sessions from your phone. The look follows Grok's dark chat UI: a list led by agent icons, floating glass buttons, and a search pill at the bottom. The approval, question, and terminal screens borrow from Codex mobile. Buttons and user bubbles are neutral; Runta orange marks state, selection, and the brand fox.

LG Liquid Glass

Follows the iOS 26 layering: controls are Liquid Glass floating over content, and content stays opaque. Glass only reads when content passes beneath it (blur, refraction, edge highlights), so every screen is drawn with "content under the controls". Glass never stacks on glass.

In SwiftUI, system navigation bars, sheets, search bars, and the keyboard are glass by default on iOS 26. Custom controls use .glassEffect(); primary buttons .buttonStyle(.glassProminent); secondary buttons .glass; adjacent buttons go in a GlassEffectContainer so they merge as they approach.

— Design system

Dark first, with a light theme (toggle at the top right). Type is the system SF Pro, with SF Mono for code and the terminal; weights follow the Mac panel: Regular 400 for body and titles in lists, Medium 500 for emphasis, Semibold 600 only for page titles. Three corner radii: capsule (buttons, fields), 18pt (cards), 32pt (sheets). Agent logos sit without backing tiles; monochrome logos invert in dark mode. Focus and selection use a thin 1pt Runta orange outline.

Q1Sign-in

Shipped: the Mac starts a device authorization for the iPhone, shows it as a QR code, and opens the dashboard's Authorize page. The iPhone gets its own token; the Mac's token is never copied. Browser sign-in stays as the fallback without a Mac.

Later: let a signed-in Fennec client approve directly (needs a Runta endpoint), and return Runta's device rate limit as 429 instead of 500.

Q2Does the terminal view ship in v1?

The chat view needs agent output parsed into structured messages, with an adapter per agent. The terminal view reuses the existing PTY stream and works for every agent, but is harder to use on a phone.

Recommendation: build both for v1. Ship the terminal first; the chat view starts with Claude Code and Codex.

Q3List titles

Decided: use the session's existing title, as the Mac panel does, or Untitled session when there is none. Session IDs (like free-bone) never appear in the phone UI.

Q4Theme

Grok is dark only. Fennec follows the system setting, with dark as the primary look. Buttons and user bubbles are neutral (Mono); orange marks state and selection. The toggle at the top right compares Warm (tinted bubbles) and Ember (deep orange buttons).

Q6Push

Lock Screen approval and Live Activities need the Runta server to send APNs pushes, plus a state channel from the cloud computer to the push service. Without push, the app refreshes state only while open.

Q7Queues on iPhone

Decided: full queue support, off by default (17). Everything the desktop does with a queue has a screen here (17–39): browse, reorder, pause/resume, threads, replies, links, images, settings, tags, agents, knowledge. Open: queue notifications while the app is closed depend on push (Q6).
